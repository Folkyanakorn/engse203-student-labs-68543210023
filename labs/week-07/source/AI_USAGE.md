# AI_USAGE — LAB 07

บันทึกการใช้ AI ระหว่างทำงาน · **ใช้ AI ได้ แต่ต้องเป็นเจ้าของโค้ดที่ส่ง**

> ผู้สอนจะสุ่มถามจากโค้ดที่ส่ง — ถ้าอธิบายไม่ได้ คะแนนส่วนนั้นจะถูกทบทวน

---

## ครั้งที่ 1

**ถามอะไร**
- CP14 ถ้าเปลี่ยน NODE_ENV เป็น production แล้วจะดูว่า log เปลี่ยนรูปแบบจริงตรงไหน

**AI ตอบว่าอย่างไร (สรุปสั้น)** 
- ให้ดูที่ Terminal ของฝั่ง API หลังจากเปลี่ยนไฟล์ .env และรีสตาร์ทเซิร์ฟเวอร์แล้ว เมื่อลองรีเฟรชหน้าเว็บ จะเห็นข้อความ Log ใน Terminal ที่ยาวและละเอียดขึ้นกว่า
    - ตอนเป็น development (ใช้รูปแบบ 'dev'): Log จะแสดงผลแบบสั้นๆ เน้นอ่านง่ายบนหน้าจอและอาจจะมีสี เช่น GET /api/requests 200 3.221 ms - 669
    - ตอนเป็น production (ใช้รูปแบบ 'combined'): Log จะเปลี่ยนรูปแบบไป ละเอียดขึ้นมาก โดยจะแสดงข้อมูล IP, วันที่และเวลา, User-Agent เหมาะสำหรับการนำไปเก็บเป็นไฟล์ข้อมูลจราจรคอมพิวเตอร์ตอนใช้งานจริง รูปแบบจะออกมายาวๆ คล้ายแบบนี้: ::1 - - [18/Sep/2026:14:03:33 +0000] "GET /api/requests HTTP/1.1" 200 669 "-" "Mozilla/5.0 (Windows NT 10.0; Win64; x64)..."


**ใช้ส่วนไหน / แก้เองตรงไหน** 
- แก้ตรงไฟล์ .env ตรง NODE_ENV=development

**เข้าใจโค้ดที่ได้มาไหม** [] เข้าใจทั้งหมด [x] เข้าใจบางส่วน [] ยังไม่เข้าใจ

## ครั้งที่ 2

**ถามอะไร**
- ทำไมห้ามส่ง stack trace ให้ผู้ใช้ตอน production

**AI ตอบว่าอย่างไร (สรุปสั้น)**
- Stack trace คือประวัติการทำงานของโค้ดที่ฟ้องว่าพังที่บรรทัดไหน ไฟล์ชื่ออะไร (เช่น TypeError at /app/src/controllers/user.js:45) ข้อมูลพวกนี้จะบอกโครงสร้างโฟลเดอร์ในเครื่องเซิร์ฟเวอร์ของเรา หรือบางทีอาจจะหลุดข้อมูลจำเพาะเช่นเวอร์ชันของ Database ออกไป ถ้าคนทั่วไปเห็นก็คงไม่อะไร แต่ถ้า "แฮกเกอร์" เห็น เขาจะรู้ทันทีว่าเราใช้เครื่องมืออะไรและควรเจาะระบบผ่านช่องโหว่ไหน โค้ดบรรทัด ...(config.isProduction ? {} : { stack: ... }) จึงเช็คว่า ถ้าเป็นระบบจริง (Production) จะไม่แนบ Stack Trace กลับไปเด็ดขาด แต่ถ้าเป็นตอนที่เรากำลังเขียนโค้ด (Development) จะส่งกลับมาให้เราหาบั๊กได้ง่ายๆ
