## 3 คำถามที่ต้องตอบ
1. ทำไมโปรเจกต์นี้เลือก SQLite แทน MongoDB
คำใบ้ — ข้อมูลเรามีโครงชัดไหม · มีความสัมพันธ์ระหว่างตารางไหม
- เพราะข้อมูลคำร้อง (requests) และข้อมูลผู้ใช้ (users) ของระบบมีโครงสร้างที่ชัดเจนรวมถึงมีความสัมพันธ์กันระหว่างตาราง การใช้ฐานข้อมูลเชิงสัมพันธ์อย่าง SQLite จึงตอบโจทย์และจัดการความสัมพันธ์ของข้อมูลได้ดีกว่าการใช้ NoSQL อย่าง MongoDB 

2. ถ้าวันหนึ่งต้องเปลี่ยนไป MongoDB จะกระทบชั้นไหนบ้าง
คำใบ้ — นึกถึง 4 ครั้งที่ผ่านมาที่แก้ชั้นเดียว · ครั้งนี้ต่างออกไปเพราะอะไร (async)
- จะกระทบ 2 ชั้นหลักๆ คือ **Service และ ชั้น Controller** 
ที่ชั้น Service ต้องเปลี่ยนคำสั่งคิวรีให้เป็นของ MongoDB และเนื่องจากการเชื่อมต่อ MongoDB จะต้องทำงานแบบไม่ซิงโครนัส (Asynchronous) จึงทำให้ต้องเข้าไปแก้ไข **ชั้น Controller** ด้วย โดยต้องเพิ่มคำสั่ง `async` ที่ฟังก์ชัน และใส่ `await` เมื่อเรียกใช้ Service เพื่อรอรับผลลัพธ์จากฐานข้อมูล

3. async จำเป็นเมื่อไร ไม่จำเป็นเมื่อไร
คำใบ้ — ต่างกันตรงที่ฐานข้อมูลอยู่ที่ไหน (ในเครื่อง vs คนละเครื่อง)
 *   **จำเป็น** เมื่อฐานข้อมูลอยู่คนละเครื่องกับ API เพราะโปรแกรมต้องใช้เวลาเดินทางผ่านเครือข่ายอินเทอร์เน็ต จึงต้องใช้ async/await เพื่อไม่ให้โปรแกรมหลักหยุดชะงักระหว่างรอข้อมูล
*   **ไม่จำเป็น** เมื่อฐานข้อมูลอยู่ภายในเครื่องเดียวกันกับ API หรือเป็นฐานข้อมูลแบบไฟล์ในเครื่อง การอ่านเขียนข้อมูลจะรวดเร็วมากจนสามารถทำงานแบบ Sync ไปตามลำดับบรรทัดได้เลยโดยไม่ต้องรอ
